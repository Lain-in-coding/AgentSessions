# Design

## Ownership and modules
The implementation checkout and raw receipts are recorded only in ignored local runtime. Shared task metadata contains branch/commit identities, never personal machine paths. Main session creates the frozen worktree and coordinates execution/commits. All workers must read shared global rules and task manifests; never revert others or write outside assigned files.

- inventory worker owns scripts/evidence/build_feedback_inventory.py and scripts/evidence/test_build_feedback_inventory.py: discovery, Windows allocated/file-identity scan, budget calculation and immutable baseline support. Expose inventory(roots, store_roots=(), discover=True), budget_status(baseline_bytes,current_bytes,free_bytes,predicted_growth_bytes=0) and atomic_json(path,payload) APIs. JSON uses schema_version=1, started_at/finished_at, roots/caches list, allocated_bytes global dedup, logical_bytes, errors, complete and alias relationships. budget_status returns allowed/review_required/reasons and project_headroom_bytes/disk_headroom_bytes/usable_headroom_bytes. GiB=1024**3, review40/hard60/free80.
- runner worker owns scripts/evidence/build_feedback_runner.py and scripts/evidence/test_build_feedback_runner.py: fixed job protocol, quiet/budget admission, Windows Job Object24GiB accounting, process capture, balanced pair execution/resumption, Cargo JSON parsing, tool environment isolation. Expose JOBS, make_protocol(...), preview_protocol(protocol, inventory_report), run_protocol(protocol_path,...). No deletion/install/global-config writes; consume approved baseline and source receipt. Fail closed for unsupported capture/unknown configs/source drift. All machine files explicitly passed/local only. Prefer Python3.10+ stdlib.
- benchmark worker owns scripts/evidence/build_feedback_benchmark.py, scripts/evidence/build_feedback_statistics.py, scripts/evidence/test_build_feedback_benchmark.py, scripts/evidence/test_build_feedback_statistics.py and docs/operations/BUILD-FEEDBACK.md. Own CLI argparse dispatch and trustworthy fixed-N comparison/bootstrap/receipts and docs. May extend runner/inventory only with owner's coordination. Modules above are intentionally independent of product crates; new test entrypoints import through importlib and stdlib unittest like existing evidence tests.

## Protocol
Version1 explicit machine-local JSON receipt includes source tree/commit and source root, compiler/Cargo identities, lock/resources hash, baseline receipt path/hash, run root, tool kind/path/version/store, full or line-tables-only debug, incremental on or one-shot-off, isolated or3lane layout, pilot/formal phase, fixed pairs5/100, jobs2/test threads2, fixed seed. make_protocol validates exact known variants; preview read-only, run requires prior protocol and review receipt when above soft budget. Frozen source roots must be dedicated Git snapshot/worktrees and not the live Beta/coordinator; coordinator descendants are allowed only in ignored runtime/evidence-output and Git must confirm the exact root. Prewarm roots cannot overlap any arm source, and outputs cannot overlap source roots. Real segment capture requires a hash-bound verified MSVC environment receipt. One pair runs baseline then candidate or reversed according to seed-balanced schedule; each arm a new dedicated worktree/target identity. Snapshot source may be materialized with git worktree only by main; runner must use preallocated source dirs or approved Git worktree creation logic, never mutate live source. Daily edit feedback uses predeclared deterministic edit solely in dedicated experimental worktrees and restores only its own edit.

## Inventory/measurement
Read Windows metadata using handles (FileIdInfo+volume identity, AllocationSize/compression/sparse handling); aliases dedup globally. Reject unknown/read failures for admission; do not call du/approximate logic formal. Discover target marker/build roots even under runtime non-target names, traverse junctions with identities and visited-set, avoid git/reference/source/cache-download scan. Live monitoring uses admission-origin C free-space minima and conservative owned JobIO write bounds, enforces owner free-space/allocated limits, and does not traverse directories during timing. Ending full scans reject overruns. Check store actual allocation independently of the whole-pair target forecast, with a separate MBX write bound; next batch forecast uses measured pilot peaks and margin. Preserve successful arm outputs until reviewed recycling by main; runner never cleans. External process activity detected before/during arm means contaminated pair; budget/resource timeout failures retained. Dedicated process Job Object with kill-on-close and suspended process launch before association. sccache server attribution must be verified; if cannot guarantee, candidate blocked. Capture commit-memory peak not claim RSS.

## Comparisons
Require same immutable source/protocol/toolchain/jobs and fixed100 completed valid pairs for formal adoption; pilot result has no adopted flag. Nearest-rankP95, paired bootstraps95% with fixed PRNG seed, distinct noninferiority/gain/storage gates. Errors/failures cannot be dropped into passing result. Full qualification also requires edit, Clippy, diagnostic, optional-feature and release receipts. No receipt => qualified false. Release qualification imports the verified official report's raw CLI observations using the approved protocol/source/validator and paired cluster statistics described below. Missing actual paired CLI observations remain unqualified with qualification_release_cli_workload_timing_unverified. Harness elapsed time is never substituted. Expose transparent ratios/speedup/storage reduction, raw statuses and reason codes.


## Release workload evidence completion

The continued task closes the missing release evidence import, without relaxing the official validator or executing real builds below disk admission. Comparisons bind a local protocol file reference (path/hash), require the normalized phase, fixed N, comparison kind, seed, pair schedule and allocations to match it, validate its immutable source/toolchain, and use only the core_beta_benchmark.py pinned in that approved source manifest and exact arm worktree. A receipt cannot select arbitrary validator code; the local sibling remains the legacy-only rejection path. Official reports must retain full baseline/build/source evidence, exact release binary artifacts, same source/lock/compiler/Cargo identity, command workspace, release-profile and deterministic dataset lineage.

Release timings come from the official full report's baseline.anchor.observations process_wall_ms values, never enclosing harness duration or inline arrays. Freeze five workload metrics: warm startup20, copied-binary cold startup20, search100, show100 and get100 per arm. Preserve their measurement states; copied-binary cold startup does not imply flushed OS caches. Baseline/candidate profiles and datasets must match. Each outer pair is the independent sampling unit: a seeded paired cluster bootstrap resamples whole paired runs, retaining all inner invocation samples and computing pooled nearest-rank P50/P95 with95% percentile intervals. Every workload's upper ratio bound must be<=1.05. Missing/changed/failed raw proof, coverage or pairing rejects qualification; legacy timing refusals remain useful reason codes.

Root owns protocol projection, task/docs/spec and scoped commits. A Trellis implement/check worker may edit only statistics/test_statistics; no Cargo, cleanup, global setup or additional stages. Synthetic passing fixtures test decisions only and are not real release qualification. Existing116-test implementation checkpoint stays historical; record the new final aggregate count after actual verification.
