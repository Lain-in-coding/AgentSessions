# 优化 50k changed-sync 提交路径

> 状态：未达标实验收尾中（2026-10-15）。父任务：`08-15-open-source-product-roadmap`。
> 正式 R4 的 shrink 门失败；按本文允许的“如实报告 + 保留现状”路径结束，
> 不把归档或草稿 PR 解释为 AC3 通过。

## Goal

按已发布基线的首个优化建议，降低 50,000 消息合成语料 changed-sync 的提交成本，
让 `initial` 与 `shrink` 的 P50 明显低于 `b0fc44d75690` 基线，同时不改变任何
用户可见语义、磁盘格式兼容性与正确性契约。基线证据：
`docs/evidence/core-beta/b0fc44d75690/manifest.md`；测量协议与验收口径已在该
清单与 `docs/performance-baseline-0.2.md` 记录。

## Confirmed background

- 基线三跑（同源、同矩阵、同冻结二进制）显示 50k 规模下 initial sync P50 约
  9.4–10.6 s、shrink 约 9.5–13.7 s，是全部被测操作中最重的两项；查询与读取
  类保持在毫秒~数百毫秒级。
- 独立 trace 试验（instrumentation 不入主延迟）显示 50k initial 的嵌套阶段中，
  单段最高为事务提交（约 3.35 s），其后是 session projection（约 2.2 s）、
  relation upsert（约 2.0 s）、manifest（约 1.2 s）等；shrink 时相应收窄。
  各标签作用域嵌套重叠、crate 时钟原点不共享，不能求和。
- 基线同时暴露：部分系列跨轮 P50 spread 超过 15%（50k shrink spread 达 42%），
  比较必须按协议披露分布，不允许只挑最快一轮。

## Acceptance Criteria

- [x] AC1：研究文档记录提交路径的代码级热点映射（trace 阶段 → 代码位置、规模
  行为、候选优化及风险），且每个被实施的优化都能对应到证据。
- [x] AC2：`cargo fmt/clippy/test` 全绿；evidence 套件与相关集成测试在全绿；
  合成语料正确性 oracle 全部通过；磁盘格式与 CLI 契约兼容性有测试或明确论证。
- [ ] AC3：按 R3 协议产出的三份新报告通过 `validate-report`/`validate-baseline`
  且满足 R4 数值门槛；未达标的实验保留原始记录并如实披露，不裁剪、不重试掩盖。
  **未满足**：initial 改善 22.7525%，shrink 改善 12.3222%；两项须均 >15%。
  O7 后续探索门也失败，已精确撤销；全部原始证据与被测源码保留。
- [ ] AC4：R6 的提交/PR/治理检查通过；若达标，性能文档新增带日期的跟进条目与
  可复现对比；父发布门未被本任务代替关闭。

## Constraints and exclusions

- 仅允许改动实现提交路径所需的产品代码与必要测试；不修改基准 harness 的协议
  语义（可复用，不为“跑得更快”改测量口径），不修改 CI 工作流、发布门、审批制度。
- 不做投机性重构、不新增用户可见功能、不改 provider 适配层契约、不引入新依赖。
- 不读取真实 transcript；全部测量继续使用合成语料；私有 runtime、原始 trace、
  失败尝试与扫描日志不进入产品提交。
- 平台范围与基线一致（本机 Windows），不宣称跨平台收益；不承诺未测得的加速数字。
- 若证据显示收益不足或风险过高，允许以“如实报告 + 保留现状”结束任务，并给出
  后续建议；任务不以“必须发布优化”为成功前提，但任何成功结论必须有 AC3 支撑。
